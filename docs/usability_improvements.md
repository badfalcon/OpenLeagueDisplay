## 高優先度

### H1. ギャラリーの「クリア」に確認も Undo もない ✅対応済み
- **現状**: `render.js` の `clearSelected()` (`#gallery-clear`) は即座に `state.selected.clear()` + `saveSelected()` を実行する (render.js:954)。localStorage も即上書きされるため復元手段がない。
- **問題**: 数十〜数百件積み上げた選択が誤タップ 1 回で全消滅する。個別トグルは「押し直しで復活」できる設計 (toggleSelected のコメント参照) なのに、最も破壊的な操作だけがノーガード。
- **改善案**: `desktop.js` の汎用 2 択モーダル `choiceModal` を流用して確認を挟む。もしくはトーストに「元に戻す」ボタンを付け、直前の Set を一定時間保持する (両方でも良い)。

### H2. ZIP 生成の失敗通知が `alert()` で、失敗一覧・再試行もない ✅対応済み
- **現状**: `zip.js` は JSZip ロード失敗 (`alert(e.message)`, zip.js:134) と部分失敗 (`alert(t("zip_failed", failed))`, zip.js:175) をブラウザ標準 `alert` で通知する。
- **問題**: アプリ全体はトースト + live region で統一されているのに、ここだけ OS ダイアログで没入感が切れる。「N 件失敗」と言われても **どのスキンが失敗したか分からず**、再試行手段もない (もう一度全件 DL し直すしかない)。
- **改善案**: ① `toast(…, "err")` へ置換。② 失敗した item を配列で保持し、完了時に「失敗 N 件を再試行」ボタン付きの結果表示を出す (progress-overlay を結果表示に流用可能)。
- **実装メモ**: ① は提案どおり (JSZip ロード失敗・部分失敗とも err トースト化)。② は「再試行ボタン」ではなく **確定前のサイレント自動再試行 1 回** (同時実行 3、`cache:"reload"`) にした — 失敗の主因は一時的な回線断で、ユーザー操作を要求せず ZIP の完成度自体が上がるため。恒久的な 404 は再失敗してそのまま件数に残る。

### H3. data.json 読み込み失敗時に再試行の導線がない ✅対応済み
- **現状**: `app.js` init() の catch はエラーページを表示して `return` する (app.js:97-105)。回復にはユーザー自身のフルリロードが必要。
- **問題**: モバイル回線の瞬断など一過性の失敗でも行き止まりになる。404 (ローカル初回) には丁寧なヒントがあるのに、ネットワーク失敗には次のアクションが提示されない。
- **改善案**: エラーページに「再試行」ボタンを置き `init()` を再実行する (もしくは `location.reload()`)。オフライン時は既存の offline-banner の文言と整合させる。

### H4. iOS Safari で検索欄フォーカス時にページが自動ズームする ✅対応済み
- **現状**: `#search` の font-size は 14px (styles.css:224) で、モバイル用 `@media (max-width:600px)` でも 16px に引き上げていない。
- **問題**: iOS Safari は 16px 未満の input にフォーカスすると強制的にページをズームする。viewport で `maximum-scale` を封じない方針 (index.html:10-12 のコメント、正しい判断) のため、この自動ズームは実際に発生し、検索のたびに画面が拡大→手動で戻す羽目になる。
- **改善案**: モバイル媒体クエリ内で `#search { font-size: 16px; }` にする (`select.ctrl-select` も同様に確認)。デザイン上 14px 相当に見せたい場合は `transform: scale()` 系ではなく素直に 16px を許容するのが安全。

### H5. カードの「＋」ボタンのタップターゲットが 28px しかない ✅対応済み
- **現状**: `.sel-checkbox` は 28×28px 固定 (styles.css:1200 付近)。タッチ端末では常時表示 (`@media (hover:none)` で opacity:1) だが、サイズはそのまま。
- **問題**: 推奨タップターゲット (44px / WCAG 2.5.8 の 24px は満たすが Apple HIG・Material の 44〜48px に満たない)。カード全面は `card-open` (ライトボックス/詳細を開く) なので、＋を外すと**意図しない画面遷移**が起きる。選択操作はこのアプリの中核動線なので誤タップの実害が大きい。
- **改善案**: 見た目は 28px のまま、タッチ環境でのみ疑似要素などで当たり判定を 44px 相当へ拡大する (`.sel-checkbox::after { position:absolute; inset:-8px; }` 等。`overflow:hidden` が効いているので配置は要調整)。
- **実装メモ**: `overflow:hidden` が疑似要素をクリップするため、**透明ボーダーで当たり判定だけを 44px に拡張** (`background-clip: padding-box` + チップの枠線は inset box-shadow へ移設) する方式にした。見た目のサイズは従来どおり (デスクトップ基準 28px / モバイル 32px。モバイルの 32px 圧縮は既存の意図的な判断なので維持)。

### H6. オンライン復帰後、読み込みに失敗した画像が自動回復しない ✅対応済み
- **現状**: 画像 404/失敗時 `imgErr` が `src` を除去して薄表示にする (render.js:1019-1024)。offline→online の遷移はバナーの表示切替のみ (app.js:611-617)。
- **問題**: 電波の谷間で開いたグリッドは復帰後も薄いカードのまま残り、「壊れている」ように見える。再描画 (ビュー遷移) するまで直らない。
- **改善案**: `online` イベントで、`img-loaded` かつ `src` なしのカード画像へ `data-src` (imgErr 時に退避しておく) を書き戻して再ロードする。もしくは現在のビューを `render()` し直すだけでも大半は回復する (スクロール位置維持に注意)。

### H7. 検索が「単一の部分一致」のみで、複数語・記号ゆれに弱い ✅対応済み
- **現状**: 検索は `String.includes` の単一部分一致 (render.js:346)。チャンピオン側はエイリアス (`Khazix` 等、記号なし) も対象なので本体はヒットするが、スキン名は表示名そのまま。
- **問題**: 具体例 — `project vayne` は「PROJECT: Vayne」(コロンがあるため部分一致不成立) にヒットしない。`dark star khazix` のような「ライン名 + チャンピオン名」の複合クエリも全滅する。ユーザーは検索が壊れていると感じる。
- **改善案**: ① クエリを空白で分割し **全トークンが当たれば一致 (AND)** にする。② 比較前に両辺を正規化 (小文字化 + `'` `:` `.` などの記号除去、`String.normalize("NFKD")` + ダイアクリティクス除去)。既存の hit() を差し替えるだけで全 view (home/lines) に効く。

## 中優先度

### M1. 検索結果のマッチ箇所ハイライトがない
カード名のどこに当たったのか視覚フィードバックがない。`<mark>` 等でマッチ部分を強調すると、ロール/地域ヒット (名前に現れない一致) との区別も付けやすい。ロール等の間接ヒットは「Mage に一致」のような小バッジで示す案もある。対象: render.js `renderChampCards` / `renderSkinCards`。

### M2. 検索欄に明示的なクリアボタンがない
`type="search"` のネイティブ × は Chrome/Safari のみで Firefox には出ない。Back ボタンで消せるが発見性が低い。入力中のみ表示する × ボタンを追加する (既存の `filter-chip` 再タップ解除と整合)。

### M3. リリース日ソートに「新しい順」がない
`sort-select` は name_asc / name_desc / release (古い順) の 3 択 (index.html:156-160)。「最近出たチャンピオンを見たい」動機が最も自然なのに新しい順がない。`release_desc` を追加し、日付欠落 (9999-99-99 扱い) は末尾固定のままにする。対象: app.js の savedSort 検証、render.js `sortedChampions`。

### M4. スキン単体へのディープリンク/共有ができない
ルーティングはチャンピオン/ライン単位まで (app.js:202-208)。ライトボックスで見ている「このスキン」を共有する手段がなく、ヘッダーの共有ボタンはページ URL のみ。`#/champion/<alias>/<skinIdx>` 等でライトボックス状態を復元できるようにし、ライトボックスのツールバーにも共有ボタンを置く。openLightbox が既に pushState している (lightbox.js:37) ので、URL 付与への拡張は素直。

### M5. ライトボックスから 1 枚だけダウンロードできない
Web 版の取得手段は ZIP のみ。今見ている 1 枚を保存するのに ZIP を作るのは過剰 (右クリック保存は知識が要るし、モバイルの長押しは fit=cover 時に意図しにくい)。ツールバーに ⬇ ボタンを追加し `fetch → saveBlob` (zip.js の `saveBlob` / `itemFor` のパス命名を流用) で単品保存できるようにする。

### M6. スライドショーが常にシャッフルで順序再生できない
`startGlobalSlideshow` は無条件 shuffle (lightbox.js:254)。ライン順・名前順に流したいケース (発表順に眺める等) に応えられない。⚙ メニューに「順番/シャッフル」トグルを追加 (localStorage 永続化、interval と同じ扱い)。

### M7. スライドショーのフルスクリーン化 (Fullscreen API) がない
ライトボックスは fixed オーバーレイでブラウザ UI が残る。壁紙アプリの後継としては全画面鑑賞ニーズが高い。⛶ (現 fit トグル) と別に全画面ボタンを追加し `requestFullscreen()`/`exitFullscreen()`。iOS Safari 非対応時はボタンを隠す (feature-detect)。

### M8. チャンピオン詳細にメタ情報が表示されない
data.json には roles / regions / release / bio があるのに、詳細ヘッダーは名前とスキン数のみ (render.js:528-551)。ロール/地域チップ (タップで該当検索へ = 既存 filter-chip の再利用)、リリース日、bio の折りたたみ表示を追加すると、検索軸の発見性 (ロール/地域で探せると気付く) も上がる。

### M9. チャンピオンカードにスキン数の表示がない
一覧カードは名前のみ。スキン数バッジがあると「どのチャンピオンを開くと収穫が多いか」を一覧で判断できる。line-card は既に count を出しており (render.js:618)、表示密度の統一にもなる。

### M10. 長いチャンピオン一覧の頭出し (A-Z ジャンプ) がない
約 170 件を 1 グリッドで縦スクロールする構造。to-top FAB はあるが「R まで飛びたい」ができない。名前順ソート時のみ、右端のアルファベットインデックス (モバイル) か、頭文字セクションヘッダー + スティッキー表示を検討。検索で代替はできるが、ブラウズ動線 (眺めて選ぶ) では別物。

### M11. Lines 一覧の並び替え・「スキン名からライン検索」ができない
ライン一覧は count 降順固定 (render.js:56)。特定ラインを名前で探すには検索するしかなく、また Lines の検索はライン名のみ対象 (render.js:594) で「Ahri で検索 → Ahri が入っているラインを出す」ができない。①名前順ソートの追加、②メンバーのチャンピオン名/スキン名もマッチ対象に加える (LINE_INDEX を使えば安価)。

### M12. PWA インストールの能動的な導線がない
manifest / SW は整備済みだが、`beforeinstallprompt` を拾ってのインストール案内 (メニュー項目や初回チュートリアルへの組み込み) がない。デスクトップ版 CTA と競合しないよう、モバイル (`isMobile()`) 限定で出すのが筋が良い。

### M13. 初期ロードがテキスト「LOADING」のみ (スケルトンなし)
data.json (~1.7MB) の取得中は `.loading` の文字だけ (index.html:165)。低速回線では白紙感が長い。カード形のスケルトングリッド (既存カードの shimmer スタイルを流用) を出すと体感が大きく改善する。取得の進捗 % (Content-Length ベース) 表示も可能。

### M14. チュートリアルが文字のみで、実 UI と紐付かない
4 ステップとも文章 (i18n.js の tut_s*_body)。「＋ ボタン」「My Gallery」の実位置を示すスポットライト/コーチマーク方式にすると初回理解が速い (対象要素に outline + 吹き出し。既存の trapFocus/inert 基盤を流用可能)。少なくとも各ステップに簡単な図解 (インライン SVG、no-binaries 方針と両立) を足したい。

### M15. ZIP ダウンロード前に総量の目安が出ない
件数は出るがサイズ感 (1 枚 ≈ 200-400KB、500 枚 ≈ 150MB 級) が事前に分からない。ギャラリーのツールバー/確認時に「約 N MB」の概算表示を追加 (枚数 × 平均サイズの概算で十分)。モバイル回線ユーザーの事故防止。

### M16. デスクトップ版に更新通知がない
インストール後は新バージョンに気付く手段がない (週次で data.json は動くがアプリ本体は据え置き)。local_app.py が自バージョンを `/api/ping` に含め、フロントが GitHub Releases の latest と比較して footer にバナーを出す案 (CSP `connect-src` に api.github.com 追加が必要。サーバ側でチェックして ping に載せる方が CSP 変更不要で筋が良い)。

### M17. デスクトップ版のポート衝突時にユーザー向けの案内がない
`local_app.py` は既定 8000 で bind し、使用中なら OSError の素の traceback で落ちる (local_app.py:717-733)。exe 利用者にはウィンドウが一瞬で消えるだけに見える。①空きポートへの自動フォールバック (ただし deep link の既定 8000 前提 (desktop.js:25) とズレる点は明示)、②少なくとも人間向けメッセージ + 待機で終了、のどちらかを入れる。

### M18. 検索中にソートが変更できない (デスクトップでも)
検索中は sort-select を隠す (render.js:210-212)。モバイルのヘッダー行崩れ対策と明記されているが、デスクトップでは幅に余裕があり「検索結果を新着順で見る」需要はある。`@media` での出し分け (モバイルのみ隠す) を検討。

### M19. スキングリッドがフル解像度スプラッシュを直接表示している (`tile`/`loading` が未使用) ✅対応済み
data.json は全 2100 スキンに `tile` (正方形サムネ、~30-60KB) と `loading` (ロード画面縦長) を持っているが、**JS はどこからも参照していない**。スキンカード・ライン一覧サムネ (`LINE_INDEX.thumb`)・壁紙確認モーダルのサムネは全て `splash` (1215×717、~150-400KB) を表示しており、1チャンピオン分のグリッドを開くだけで数MB、Lines 一覧・レア度フラット表示では数十MB を読み込み得る (loading=lazy で可視域に限定はされるがモバイル回線では依然重い)。カード表示を `s.tile || s.splash` に切り替えれば帯域を概ね 1/5〜1/10 にできる。**トレードオフ**: tile は顔中心の正方形クロップで、現在の「横長スプラッシュを cover で見せる」画作りと印象が変わる (16:9 カードに正方形画像を cover すると上下が切れる)。ライトボックス/ZIP/壁紙は従来どおり splash。要デザイン判断だがモバイル体感への効果は大きい。対象: render.js `skinCardHTML`、state.js `buildIndexes` (thumb)、wallpaper.js `wp-grid`。
- **実装メモ**: `state.js` に `cardThumb(s) = s.tile || s.splash` を一元化し、スキンカード・ライン一覧サムネ・壁紙確認サムネの 3 箇所を切替 (旧 data.json はフォールバックで従来どおり)。tile は `*_splash_tile_*.jpg` (スプラッシュ本体の顔中心クロップ) なので画の系統は連続する。16:9 カードでの上下クロップは `object-position: center 30%` で顔寄りにバイアス。ライトボックス/ZIP/壁紙適用は full splash のまま。**サンドボックスでは CDragon 遮断のため実画像での見た目確認は未実施** — 実機で気になる場合は `cardThumb` の 1 行を `s.splash` に戻せば全面復元できる。

### M20. ZIP 保存成功時のフィードバックが無い ✅対応済み
`downloadAsZip` は失敗時のみトーストを出し、全件成功時は無言で終わる (保存はブラウザの DL 通知任せ)。「Saved ✓」の成功トーストを 1 行足すと完了が明確になる (壁紙適用側は Done モーダルまで出しているのと非対称)。対象: zip.js。
- **実装メモ**: 全件成功時に `zip_saved` トースト (default + ja_jp、他ロケールは英語フォールバック) を表示。部分失敗時は従来どおり err トーストのみ。

## 低優先度 (磨き込み)

- **L1. スライドショー間隔がサイクルボタン**: ⏱ を押すたび 3→5→7→10→15→30s と巡回 (app.js:550-556)。30s から 3s に戻したい時に 5 連打が必要。⚙ メニュー内なので素直に選択リストにできる。加えてこの値は**永続化されていない** (壁紙側 `LS_WP_INTERVAL_KEY` はあるのにビューア側はない) — 揃えると再訪時に設定が残る。
- **L2. スライドショー中の任意スライドへのジャンプ不可**: カウンター表示のみ。サムネイルストリップ or カウンタータップでグリッドへ戻る等。
- **L3. ライトボックスにズーム/パンがない**: ピンチはページ全体ズームになる。ダブルタップ/ホイールでの画像ズーム + ドラッグパン (fit トグルの上位互換)。
- **L4. 動画スキンの再生コントロールがない**: muted+loop 固定 (lightbox.js:133-155)。一時停止・頭出し程度は欲しい (スライドショー Pause は静止画タイマーのみで video は止まらない点も確認対象)。
- **L5. 言語メニューの矢印キー移動非対応**: 意図的に disclosure + Tab 運用 (index.html:120-124 コメント) だが、20 項目は Tab 連打が長い。↑↓ での移動だけ足しても disclosure セマンティクスとは矛盾しない。
- **L6. ギャラリーのグルーピング/並び順**: 常に名前順 (render.js:747-752)。チャンピオン別グループ表示や「追加順」トグル。
- **L7. 選択スキンのオフラインキャッシュ (opt-in)**: 画像は意図的に非キャッシュだが、「ギャラリーの N 枚だけオフライン保持」は PWA 価値を上げる (Cache Storage、上限と削除 UI 付き)。
- **L8. タブ/ボタンへの件数表示**: My Gallery バッジは実装済み。Skin Lines タブにライン総数を出す等は情報過多と紙一重なので低。
- **L9. ライトボックスの Home/End キー**: 先頭/末尾ジャンプ。
- **L10. 詳細ビューの ‹ › にキーボードショートカットがない**: ライトボックス外の ←→ は空いているが、スクロール操作との衝突を要検討。
- **L11. トーストの表示時間が固定 2.6 秒**: `wallpaper_failed` 等の長文エラーは読み切れないことがある。文字数に応じた延長、または err 種別のみ長め (5秒程度) にする。対象: local.js `toast`。
- **L12. 開きっぱなしのタブ/ネイティブ窓が古い data.json のまま**: data.json はロード時に 1 回 fetch するのみで、週次更新が長寿命のウィンドウに届かない。`visibilitychange` で前回取得から 24h 超なら再取得 (または「新しいデータがあります」バナー) を検討。
- **L13. manifest の磨き込み**: `shortcuts` (My Gallery / Slideshow への直接ジャンプ) と `form_factor: narrow` のスクリーンショットが無い。追加するとインストール UI とホーム画面長押しメニューが充実する (スクリーンショットは no-binaries 方針との整合を要確認 — 既存 screenshot.png と同類なら許容範囲)。

## 要オーナー判断 (既存の設計判断と衝突する候補)

これらは CLAUDE.md / コード内コメントで**意図して現状の形にした**と明記されているもの。改善候補ではあるが、先に方針の再確認が必要。

- **T1. 検索クエリ/ソートの URL 化**: 現状「スコープを狭く保つ」ため意図的に非対応 (app.js:208-209)。ただし検索結果が共有・ブックマークできない実害はあり、`#/?q=` を足すなら履歴 snapshot 機構 (searchQuery を history.state に保存する既存実装) との整合を設計し直す必要がある。
- **T2. SW を network-first に統一している件**: 開発時の「反映されない罠」回避が理由 (sw.js:5-9)。回線が細い実ユーザーには stale-while-revalidate + 更新トースト (「新しいバージョンがあります → 再読み込み」) の方が初期表示は速い。開発体験とのトレードオフ。
- **T3. ライトテーマ非対応**: 深い黒紫×金はブランドそのもの (CLAUDE.md)。`prefers-color-scheme: light` 対応はコスト大でブランド毀損リスクあり。現状維持が妥当と思われるが、要判断事項として記録。
- **T4. クロマ/その他アセット非対応**: CDragon にはクロマ等もあるが、スプラッシュ特化が現在のスコープ。対応するなら data.json スキーマから設計が要る。

## 対応済みで水準が高い点 (再対応不要)

洗い出しの網羅性のため、調査済みで**問題なし**と判断した領域を記す。

- **モバイル**: 下部固定ナブ + safe-area、ピンチズーム許容、スワイプ、タップでのクローム開閉、fit トグル。
- **フィードバック**: オフラインバナー、トースト + SR ミラー、進捗オーバーレイ (キャンセル可)、壁紙適用の進捗ポーリング、共有ボタンのコピー完了表示。
